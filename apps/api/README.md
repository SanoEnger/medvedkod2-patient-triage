# Независимый NLP-модуль МедВед.Код2

Модуль Волосникова извлекает признаки из **синтетических** русскоязычных жалоб.
Работает без FastAPI, PostgreSQL, React и MAX. Не ставит диагноз, не назначает
лечение, не определяет срочность и не формирует рекомендации пациенту.

## Установка и запуск

Python 3.12+; команды выполняются из `apps/api`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest -q
python -m app.integrations.groq
```

Если в окружении установлены посторонние pytest-плагины, можно изолировать
проверку: `$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'` перед запуском pytest.
В Windows среда запуска должна разрешать служебное loopback-соединение asyncio;
это не запрос к Groq. Для корректного вывода русского текста в старых терминалах
можно установить `$env:PYTHONIOENCODING='utf-8'`.

Последняя команда выводит JSON для встроенного синтетического примера в mock-режиме.
Тесты используют только локальные заглушки HTTPX, сетевые подключения не нужны.
Проверено также на Python 3.13; отдельный запуск на 3.12 пока не выполнен.

## Использование

```python
from app.integrations.groq import MockGroqClient, SymptomExtractor

extractor = SymptomExtractor(MockGroqClient())
result = await extractor.extract("У меня сильно болит грудь, тяжело дышать")
data = result.model_dump(mode="json")
```

Для живого адаптера явно подставьте `GroqClient(GroqSettings.from_env())`.
Переменные окружения: `GROQ_API_KEY`, `GROQ_MODEL`, `GROQ_TIMEOUT_SECONDS`
(по умолчанию 7 секунд, допустимо больше 0 и до 60). Модель выбирается в аккаунте
Groq с поддержкой JSON mode; намеренно нет зашитого имени модели.
`.env.example` содержит только пустые значения; автоматической загрузки `.env` нет.
При отсутствии ключа или модели возвращается fallback. Не передавайте реальные
медицинские данные: прототип не обеспечивает их обезличивание.

Используется HTTPS Chat Completions через HTTPX, `response_format=json_object`
и отдельная строгая Pydantic-проверка. JSON mode гарантирует формат JSON, но не
соблюдение схемы. Справка: https://console.groq.com/docs/api-reference и
https://console.groq.com/docs/structured-outputs . Повторы запросов отключены;
общий дедлайн ограничивает запрос целиком. Перенаправления не разрешены.

## Временный контракт

Вход — строка не длиннее 10000 символов. Пустой ввод не отправляется в сеть.
Неверный тип или превышение лимита вызывает фиксированную `ValueError` без ввода.
Результат — `ExtractionResult`:

```json
{
  "symptoms": [
    {"code": "chest_pain", "evidence": "болит грудь", "status": "present", "location": null, "duration": null},
    {"code": "dyspnea", "evidence": "тяжело дышать", "status": "present", "location": null, "duration": null}
  ],
  "details": [],
  "needs_clarification": true,
  "source": "groq",
  "mode": "mock",
  "fallback_reason": null
}
```

`status`: `present`, `negated`, `uncertain`. `evidence`, `location`, `duration` —
дословные фрагменты исходного текста. `details` содержит тип и дословный фрагмент:
`age`, `temperature`, `pregnancy`, `history`, `medication`, `allergy`.
Fallback извлекает только первые три типа. Это упоминания, а не подтверждённые
клинические факты. Локализация и длительность могут отсутствовать; fallback
присоединяет длительность только при единственном распознанном симптоме.

Коды признаков:

| Код | Значение |
| --- | --- |
| chest_pain | Боль в груди |
| dyspnea | Затруднённое дыхание без подтверждения покоя |
| dyspnea_rest | Явное упоминание одышки в покое |
| loss_of_consciousness | Потеря сознания |
| seizure | Судороги |
| bleeding | Кровотечение |
| abdominal_pain | Боль в животе |
| headache | Головная боль |
| fever | Упоминание температуры или жара |
| head_injury | Травма головы |
| facial_asymmetry | Асимметрия лица |
| speech_difficulty | Нарушение речи |
| arm_weakness | Слабость или невозможность поднять руку |
| throat_swelling | Отёк горла |
| rash | Сыпь |
| cough | Кашель |
| nausea | Тошнота |

FAST, анафилаксия и другие диагнозы не выводятся из сочетаний признаков.
Порог температуры и возраст ребёнка не оцениваются этим модулем.

`source=groq` означает валидный ответ адаптера, включая mock; для отличия есть
`mode=live|mock`. В объединённом ответе также сохраняются локальные признаки.
`source=fallback` означает отказ адаптера, конфигурации или проверки ответа.
`fallback_reason` — фиксированный код причины, без исходного текста и тела ошибки.
Mock имеет отдельные фиксированные ответы для двух примеров; остальные тексты
получают пустой mock-ответ и независимые локальные признаки.

## Безопасность и границы

Внешние SafetyRules должны проверять исходный текст **до ожидания Groq**, а затем
повторно проверять данные после извлечения. Нельзя использовать NLP как единственный
механизм обнаружения экстренных состояний. Сбой или пустой результат не разрешают P3.

Независимые локальные признаки добавляются к ответу модели первыми: LLM не может
удалить их или заменить отрицанием. При конфликте могут остаться два статуса;
внешние правила должны рассматривать конфликт как неопределённость, а не отмену
сигнала. Лимиты выдачи — 40 симптомов и 20 дополнительных сведений.

Локальные регулярные выражения распознают ограниченные формулировки. Отрицания,
история и вопросы обрабатываются консервативно как `uncertain`; это не полноценный
разбор русского языка. Возможны пропуски, ошибки области отрицания и ложные
совпадения. `needs_clarification` сейчас всегда true: полноту анамнеза модуль
не может подтвердить без контракта опросника.

Системный prompt отделён от пользовательских данных. Схема запрещает лишние поля,
включая диагноз, дозировку и срочность. Проверяется наличие дословных свидетельств.
Эти меры не гарантируют семантическую истинность ответа и не устраняют prompt
injection полностью. Даже цитата из текста может быть неверно интерпретирована.
Не отображайте свидетельства как медицинские рекомендации или HTML.

Модуль не пишет жалобы, ключи и ответы в логи; ожидаемые исключения адаптера
содержат только фиксированные коды и не сохраняют исходную цепочку ошибок.
Не включайте HTTP wire/debug-логирование или захват локальных переменных в системе
мониторинга: сторонние инструменты могут записывать чувствительные данные.

## Подключение к будущему backend

Вахрушев может передать экземпляр `SymptomExtractor` через dependency injection
и вызвать `await extractor.extract(text)` в своём сервисе. HTTP-маршруты и
зависимость FastAPI здесь не создаются. Отмена async-задачи распространяется наружу.
После возврата нужно передать исходный ввод и результат независимым SafetyRules,
затем TriageEngine; приоритет внешних правил абсолютный.

Нужно согласовать: коды и статусы, семантику конфликта, формат анамнеза, отдельное
происхождение каждого признака, лимиты, правила уточнения и обработку UNKNOWN.
Автономные тесты проверяют извлечение и отказоустойчивость. Они **не подтверждают**
полное прохождение T01–T10, EMERGENCY_STOP или экран 103/112: это зона SafetyRules.
Живой запрос к Groq и конечная интеграция с backend пока не проверялись.
