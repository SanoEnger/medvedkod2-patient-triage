# Голосовой ввод внутри MAX

## Что проверено

- Наш frontend не отдаёт запрещающих `Permissions-Policy` или `Feature-Policy`.
- HTTP-запрос с синтетической русской записью к опубликованному voice API возвращает 200 и распознанный текст.
- Раньше `VoiceInput` вызывал `getUserMedia()` напрямую. Теперь при наличии `window.WebApp.PermissionsManager` он сначала инициализирует менеджер и запрашивает только `mic` после нажатия пользователя, затем получает поток браузера. Отказы MAX обрабатываются отдельно. Без предоставленного Bridge действует обычный браузерный запрос; приложение не обращается к чужим frames в обход origin-защиты.
- До остановки Computer Use у внешнего iframe MAX прочитано:
  `allow="camera 'none'; microphone 'none'; geolocation; clipboard-write"`.
- Публичная оболочка организаторов создаёт внутренний iframe с `allowFullScreen`, без `allow="microphone"`. Наличие класса PermissionsManager в SDK не означает вызов его методов оболочкой.

## Недостающий этап интеграции

В документации MAX описан отдельный запрос доступа mini-app. Начальный запрет микрофона в веб-клиенте может быть штатным до согласия пользователя. Поэтому сам по себе `microphone 'none'` не доказывает ошибку организаторов.

Документированный вызов для владельца действующего MAX Bridge:

```js
// Из обработчика пользовательского нажатия в зарегистрированном mini-app.
const permissions = window.WebApp.PermissionsManager;
if (!permissions.isInited) await permissions.init();
await permissions.requestAccess('mic', 'Голосовой ввод ответа в анкете');
```

SDK использует аргумент `mic`, а не браузерное имя `microphone`. Камеру запрашивать не нужно. При отказе следует предложить пользователю настройки доступов MAX отдельной кнопкой, а не открывать их автоматически.

Наш сайт является внешним iframe: он получает Core JWT, а не MAX launch context. Простое подключение SDK внутри него не подтверждает наличие рабочего канала с MAX. Вызов должен выполнить оболочка с действующим MAX Bridge, либо оболочка должна предоставить согласованный канал для такого запроса. На внутреннем iframe требуется делегирование `allow="microphone"` после разрешения доступа родителю; дочерний сайт не может отменить запрет предка.

## Локальная диагностика

При ошибке компонент сохраняет только этап, фиксированный код исключения, состояние политики микрофона, наличие защищённого контекста и вложенного окна. Текст исключения, URL, токены, названия устройств и аудио не включаются. Сбой создания или запуска MediaRecorder больше не показывается как отказ разрешения микрофона.

Источники: [MAX Bridge — PermissionsManager](https://dev.max.ru/docs/webapps/bridge/), [MDN — getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
