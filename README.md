# МедВед — навигатор пациента

Рабочая интеграционная ветка — `develop`. `main` предназначена для проверенного
релиза. Здесь собраны React-оболочка, FastAPI backend, детерминированные правила
безопасности, MAX server-to-server adapter и автономный Groq NLP-модуль.

Это демонстрационный прототип для синтетических данных. Frontend подключает
backend для MAX-авторизации; SessionService использует NLP для свободных жалоб.
Интерфейс опросника ещё не подключён к API. PostgreSQL и полноценный
пользовательский опросник ещё не реализованы. Наличие компонентов в одной ветке
не означает готовность медицинского сервиса или сквозной интеграции MAX.

## Компоненты и запуск

- [Backend и API](apps/api/README_BACKEND.md) — конфигурация, запуск сервера,
  in-memory сессии и правила безопасности.
- [Groq NLP](apps/api/README.md) — установка, mock, fallback и формат извлечения.
- [React UI](apps/web/README.md) — запуск, demo/production-сборки и браузерные тесты.
- [MAX](apps/api/MAX_INTEGRATION.md) — границы серверной проверки host-токена.

Для общей проверки Python-компонентов из `apps/api`:

```powershell
python -m pip install -e ".[test]" -r requirements-backend.txt
python -m pytest -q
```

Для проверки frontend из `apps/web`:

```powershell
npm ci
npm run lint
npm run build
npm run build:demo
npx playwright install chromium
npm test
```

Не передавайте реальные медицинские данные и не добавляйте секреты в Git.
Клиническая проверка правил и проверка реального MAX остаются отдельными задачами.

## Подробности текущей UI-поставки

Первая задача: `feature/smirnov-react-ui`. React + TypeScript + Vite, адаптивная оболочка и общие компоненты. Работает автономно в браузере на синтетических данных. Медицинский опрос, REST API и PostgreSQL будут реализованы в отдельных ветках.

## Запуск

Нужны Node.js 22.12+ и npm. Все команды выполняются из `apps/web`:

```powershell
cd apps/web
npm ci
npm run dev
```

Открыть адрес Vite из терминала (обычно `http://127.0.0.1:5173`). В режиме разработки mock host включён по умолчанию. Для явной настройки скопировать `apps/web/.env.example` в `apps/web/.env.local`. Секреты в `VITE_*` запрещены: эти значения доступны браузеру.

```powershell
npm run lint
npm run typecheck
npm run build
npm run build:demo
npm run preview
```

`build` создаёт production-сборку без деморежима, если `VITE_HOST_MODE` не задан. Без подключённого адаптера она показывает сообщение о недоступном запуске. `build:demo` явно включает mock host через `.env.demo`; последующий `preview` показывает демо по `http://127.0.0.1:4173`. Перед production-сборкой удалить `VITE_HOST_MODE=demo` из `.env.local`, если он был добавлен. Демоартефакт не является production-релизом.

## Проверки браузера

```powershell
npx playwright install chromium
npm test
```

Если оболочка npm в Windows завершается без диагностики, прямой запуск тех же тестов: `node node_modules/@playwright/test/cli.js test --workers=2`.

Playwright сам поднимает Vite на порту 4173; остановить `preview`, если он занимает этот порт. Проверки покрывают загрузку, временный сбой и повтор, форму, сброс, возврат и фокус, клавиатуру, отсутствие горизонтальной прокрутки на 360×640, 390×844, 768×1024, 1440×900 и работу при уменьшении высоты viewport до 380 px. Последнее имитирует изменение доступной области при клавиатуре, но не заменяет проверку на телефоне.

Для ручной проверки временного сбоя открыть `/?demo=error-once`: mock host один раз отклонит запуск, кнопка «Попробовать снова» повторит инициализацию. Параметр учитывается только в деморежиме.

## Состав оболочки

- `src/app/` — `AppShell`, инициализация и переключение приветствия/примера.
- `src/components/` — кнопка, карточка, подписанные select/textarea, загрузка и ошибка.
- `src/pages/` — приветствие и автономный пример формы; текст остаётся в DOM до выхода из примера, без отправки и постоянного хранения.
- `src/max/` — интерфейс `MaxHostAdapter` и изолированный mock host.
- `src/styles/` — палитра и адаптивные стили; safe-area, `dvh`, прокрутка страницы, видимый фокус и reduced motion.

Палитра: фон `#F8F6FF`, акцент `#7560B8`, дополнительный фон `#E9E2FA`, заголовки `#342B56`, вторичный текст `#78718D`, карточки `#FFFFFF`. Вторичный цвет используется на белых карточках; на лавандовых поверхностях мелкий текст темнее для читаемости.

Кнопка «Аа Читаемость» под шапкой включает повышенную читаемость: на `.app-shell` появляется `data-readability="enhanced"`. Через CSS-переменные текст меняется на `#251A45`, кнопки на `#543B91`, рамки становятся контрастнее; основной текст, поля и кнопки увеличиваются до `1.25rem` (20 px при стандартных настройках браузера). Лавандовый фон и белые карточки сохраняются. Переключение не пересоздаёт экраны и сохраняет введённый текст, выбор и сообщение формы. Настройка действует до перезагрузки страницы.

В обоих режимах проверяются ширины 320, 360 и 390 px с текстом 100% и 200%, возврат, ошибка, клавиатура и сохранение формы. Короткие демонстрационные варианты «Пример 1 / Пример 2» помещаются в нативном select при увеличении шрифта. Реальный опрос и проверки контейнера MAX остаются задачами интеграции.

## Точка интеграции MAX

`App` принимает `hostAdapter?: MaxHostAdapter`; метод `initialize()` возвращает `HostContext` с режимом `demo | max`. Адаптер передаётся в `src/main.tsx`. Это предложенная граница UI, требующая согласования с Волосниковым и Вахрушевым. Возврат `mode: 'max'` сам по себе не подтверждает авторизацию.

После получения спецификации организаторов владельцы интеграции должны подключить проверенный запуск: backend-валидацию контекста/токена, Bridge либо согласованный протокол host, origin allowlist и правила встраивания. Произвольные query-параметры и `postMessage` не используются для доверенной авторизации. Внешний MAX SDK в этой ветке не подключён.

Реальный контейнер MAX, Android/iOS, физическая экранная клавиатура и возврат в меню host требуют отдельного прогона с организаторами. Медицинские сценарии T01–T17 этой оболочкой не подтверждаются.
