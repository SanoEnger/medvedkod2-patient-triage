# Временная проверка входа через компьютер капитана

В Vercel установлен регион Мумбаи (`bom1`). Прямое TCP-соединение из Vercel с
Core организаторов недоступно, поэтому только проверка входа проходит через
локальный relay и Cloudflare Quick Tunnel. Сайт, Groq и Neon остаются на Vercel.

Схема: Vercel → HTTPS Cloudflare Tunnel → `127.0.0.1:8765/resolve` → HTTPS Core.

Relay принимает `POST /resolve` с JSON `{"token":"<пользовательский JWT>"}`
и отдельным `Authorization: Bearer <CORE_RELAY_TOKEN>`. Этот секрет не является
токеном организаторов. На Core relay передаёт JWT в query и сервисный токен команды
в Authorization, как требует инструкция. В ответ возвращается только `_id`.
При недоступности Core или ошибке проверки вход запрещается.

## Текущее локальное окружение

- Процессы работают в фоне, без открытых окон. Компьютер должен быть включён.
- Секреты, журналы и PID находятся в игнорируемой папке `.local/core-relay/`.
- HTTP access log отключён, JWT передаётся на relay в теле POST, не в URL.
- Для ручного запуска используется задача Windows `MedVedCoreRelay` в планировщике.
- Случайный URL Quick Tunnel сохраняется в `.local/core-relay/url.txt`.
- При пересоздании туннеля URL меняется; установленный автозапуск обновляет
  адрес в Vercel и повторно публикует текущую production-версию API.

## Автозапуск на ноутбуке

Установлена задача Windows `MedVedCoreRelay`, запускаемая при входе текущего
пользователя в Windows. Она работает без окна, в том числе от батареи.
`apps/api/scripts/relay_autostart.py` следит за процессами и перезапускает их
после остановки. Второй экземпляр не запускается.

После перезапуска компьютера Quick Tunnel получает новый адрес. Supervisor ждёт
доступности туннеля, обновляет только `CORE_RELAY_URL` проекта `medved-api`
в production/preview и повторно публикует текущую production-версию API.
Новые коммиты из веток автоматически не публикуются. До завершения публикации
вход может быть временно недоступен. Секреты не меняются и в журнал не выводятся.

Конфигурация и журнал — `.local/core-relay/autostart.json` и `autostart.log`.
Для переустановки задачи используется `apps/api/scripts/install_relay_autostart.ps1`
с параметрами `-Python` (полный путь к python.exe) и `-VercelCli` (полный путь
к установленному vc.js). Нужны существующий `private.env`, cloudflared и
сохранённая авторизация Vercel CLI. При переносе папки проекта задачу надо
переустановить. Автозапуск не отменяет необходимость включённого компьютера
и подключения к интернету; из сна он компьютер не выводит.

## Настройки API на Vercel

`CORE_RELAY_URL` — HTTPS-адрес туннеля без `/resolve`.
`CORE_RELAY_TOKEN` — отдельный серверный секрет длиной не менее 32 символов.
`CORE_TIMEOUT_SECONDS=8` — ограничение ожидания relay.

Для возвращения прямого соединения удалить `CORE_RELAY_URL` и повторно
опубликовать API. Сам Core и его проверка JWT не заменяются локальной проверкой.
