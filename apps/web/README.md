# МедВед — опросник пациента

Общий запуск frontend + API + PostgreSQL одной командой: [Docker](../../docs/DOCKER.md).

Ветка feature/smirnov-questionnaire: React-опросник по контракту FastAPI. Сохраняет прежнюю палитру, логотип и режим повышенной читаемости.

## Запуск интерфейса

Node.js 22.12+ и npm. Из корня репозитория:

```powershell
cd apps/web
npm ci
npm run dev
```

Vite показывает адрес, обычно http://127.0.0.1:5173. Фронтенд всегда использует REST API; автономные заранее заданные результаты в приложении отключены.

Для явной настройки скопируйте .env.example в .env.local. Секреты в VITE_* запрещены: переменные доступны браузеру.

## Режимы

| Настройка | Поведение |
| --- | --- |
| VITE_HOST_MODE=demo | Существующая локальная авторизация backend; настоящие API и БД |
| Запуск с host JWT | Обмен JWT и настоящий API |
| VITE_API_ORIGIN | Публичный origin API; без него используется origin страницы |

Параметр scenario не подменяет результат в приложении. Отказ API показывается как ошибка; ответы и рекомендации не создаются фронтендом. Фикстуры остаются только для автоматических тестов.

## Локальный frontend + API + PostgreSQL

Подготовьте БД, ключи и HTTPS по [инструкции PostgreSQL](../api/README_POSTGRES.md). Запустите API из apps/api через run_demo.ps1.

Для frontend в apps/web/.env.local:

```dotenv
VITE_HOST_MODE=demo
VITE_SURVEY_MODE=api
VITE_API_ORIGIN=https://localhost:8443
```

Перезапустите Vite после изменения .env.local. Браузеру нужно доверие к локальному CA. В backend CORS_ORIGINS должен включать точный адрес frontend, например http://127.0.0.1:5173. Если API размещён на том же публичном origin, настройте маршрутизацию /api/v1 к backend.

Для MAX frontend получает JWT через ?token=... и сразу удаляет его из URL. Backend обменивает JWT на собственный bearer-токен; тот остаётся только в памяти и используется для опроса. Service token и ключи БД остаются на сервере. Production-сборка без host-контекста и без явного demo-режима не создаёт доверенную MAX-сессию.

Поля sex, height_cm, weight_kg и lactation в patient_context и hospitalizations_last_year в medical_history добавлены в backend этой ветки как необязательные. Для них не нужна новая миграция: ответы уже хранятся зашифрованным JSON. Frontend следует запускать с обновлённым backend; старый строгий контракт отклонит новые поля.

## Сценарий

Создание обращения возможно только после принятия дисклеймера. Пять шагов:

1. Основная жалоба и свободный текст.
2. Температура, возраст, пол, рост и вес. При выборе женского пола появляются вопросы о беременности и грудном вскармливании.
3. Локализация, длительность, выраженность и уточнения.
4. Экстренные признаки. Ответ «Да» сразу отправляется на серверную проверку.
5. Хронические заболевания, лекарства, аллергии, операции, госпитализации, наследственность и необязательные привычки.

У каждого поля анамнеза есть независимая отметка «Нет»: она отправляет ['Нет'] в существующем списке, скрывает поле и сохраняет черновик для отмены отметки. Пустое поле остаётся пустым списком. Неизвестные числовые значения и признаки сохраняются как null, а не как отрицательные ответы. Списки анамнеза ограничены 10 значениями по 120 символов. Поля не собирают ФИО, телефон, адрес, полную дату рождения и документы.

Срочность и рекомендации берутся из API. При UNKNOWN показывается необходимость уточнения, без придуманной самопомощи. Экстренный экран имеет приоритет над результатом и ошибками, показывает 103/112 и не допускает возврата к обычному опросу. Запоздалый обычный ответ не скрывает предупреждение.

«Назад» отправляет target_step серверу. Последующие актуальные ответы и результат сбрасываются; локальные черновики остаются для повторного подтверждения. После сбоя отправки повтор использует прежние UUID и тело ответа. Конфликт требует обновления состояния.

Удаление требует подтверждения. Локальные ответы очищаются после успешного DELETE. При ошибке удаления обращение остаётся на экране. Новый опрос начинается с нового согласия; завершённое обращение автоматически не удаляется.

## REST-контракт

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | /api/v1/auth/launch | Demo/host-авторизация |
| POST | /api/v1/sessions | accepted_disclaimer: true |
| GET | /api/v1/sessions/{id} | Состояние, прогресс, результат |
| POST | /api/v1/sessions/{id}/answers | question_key, value, idempotency_key |
| POST | /api/v1/sessions/{id}/back | target_step с нуля |
| POST | /api/v1/sessions/{id}/triage | Пересчёт/подтверждение результата |
| DELETE | /api/v1/sessions/{id} | Удаление с ответом 204 |

Типы и проверка ответов: src/api/contracts.ts и src/api/client.ts. Тестовые фикстуры отделены в src/api/mock.ts и не импортируются приложением. В реальном режиме неподтверждённый или некорректный ответ приводит к ошибке; явный экстренный сигнал сохраняет приоритет.

Медицинские данные, bearer-токены и черновики не сохраняются в localStorage/sessionStorage и не выводятся в console. После перезагрузки страницы память клиента очищается; данные настоящего API остаются в БД в пределах её TTL. Медицинский текст выводится как текст, без HTML-интерпретации.

## Читаемость и адаптивность

Переключатель «Аа Читаемость» сохраняет текущие поля и состояние опроса. На корневом элементе появляется data-readability="enhanced"; CSS-переменные увеличивают текст и контраст. На узком экране переключатель расположен под шапкой. Кнопки и карточки растут по содержимому.

Проверки покрывают 320/360/390 px, текст 100%/200%, оба режима, все шаги, итог, диалог удаления и экстренный экран, а также 768×1024 и desktop. Логотип: public/brand/medved-mark.png.

## Проверки и сборка

```powershell
npm run lint
npm run typecheck
npm run test:unit
npm test -- --workers=1
npm run build
npm run build:demo
```

Vitest + React Testing Library проверяют логику и формы. Playwright проверяет браузерную навигацию, доступность, адаптивность, чтение и REST-клиент с синтетическими ответами.

Если Chromium ещё не установлен:

```powershell
npx playwright install chromium
```

build создаёт production-сборку; build:demo — сборку с локальной авторизацией backend и настоящим API. Для запуска MAX нужна сборка с host-контекстом.

## Сквозная проверка с настоящей БД

Тесты live запускаются отдельно от обычных браузерных проверок. Они используют локальный HTTPS API, demo-авторизацию и синтетические обращения. Чужие обращения не удаляются; созданные тестами ID очищаются после сценария.

В первом PowerShell, из apps/api, с активированным Python-окружением и подготовленным backend.env:

```powershell
docker compose --project-name medved_questionnaire_test --env-file ../../.local/runtime/backend.env -f compose.postgres-test.yaml up -d --wait
$env:DATABASE_URL = "postgresql+asyncpg://medved_test:synthetic-test-only@127.0.0.1:55433/medved_test"
$env:API_PORT = "8444"
$env:CORS_ORIGINS = "http://127.0.0.1:4174"
$env:NLP_MODE = "mock"
python -m alembic -x env_file=../../.local/runtime/backend.env upgrade head
.\run_demo.ps1
```

Во втором PowerShell, из apps/web:

```powershell
npm run test:live
```

Playwright поднимает frontend на 4174. Только тестовый browser context допускает локальный сертификат без системной установки CA; приложение проверку TLS не отключает. MEDVED_LIVE_API_ORIGIN позволяет задать другой локальный HTTPS origin. Подключение к произвольному удалённому серверу для этих тестов запрещено.

После проверки остановите тестовый API через Ctrl+C и удалите его отдельный контейнер:

```powershell
docker compose --project-name medved_questionnaire_test --env-file ../../.local/runtime/backend.env -f compose.postgres-test.yaml down
```

Запуск в настоящем контейнере MAX и проверка на Android/iOS выполняются с организаторами после размещения и получения действительного host JWT.

## Чат с МедВедом

На главной есть «Начать чат с МедВедом» и «История чатов». Пока идёт опрос, историю можно просматривать, а создание чатов и отправка сообщений приостановлены. После результата «Уточнить у МедВеда» открывает связанную переписку. Результат опроса можно раскрыть прямо в чате.

После перезагрузки история загружается с сервера. При истечении входа откройте
приложение заново в MAX. Сохранённая незавершённая отправка повторяется с тем же
ID. Экстренный чат доступен для чтения с кнопками 103/112. Удаление из истории
требует подтверждения. Для чата по опросу удаляются также ответы и результат.

В тестовом режиме `NLP_MODE=mock` API возвращает локальный ответ. В режиме
`NLP_MODE=live` для ответа нужны `GROQ_API_KEY` и `GROQ_MODEL` на сервере.
